## 3. Этапы

Порядок соответствует направлению из `CLAUDE.md`: сначала Star Rail, потом Genshin, потом
Zenless Zone Zero. В каждом этапе несколько функций. Каждая функция начинается с падающего
теста и заканчивается сценарием в `frontend/e2e/app.spec.ts`.

### Этап 17. Импорт с ПК и сохранность истории

1. **Свой PowerShell-скрипт для ссылки на историю** (README, пункт 0). Владелец одобрил;
   делается последним пунктом этапа, после экспорта, импорта UIGF для Genshin и статистики.
   - Два скрипта: Genshin и Star Rail. Каждый только читает файлы игры и выводит ссылку.
   - Скрипт ничего не отправляет в сеть и не пишет на диск.
   - Где игра хранит ссылку, берётся из открытых трекеров, прочитанных и названных в README.
     Чужой код не копируется без проверки лицензии.
   - Скрипт отдаётся с нашего сайта как текст, страница показывает его целиком до запуска.
   - Проверка: тест на содержимое скрипта (нет сетевых вызовов, нет записи), e2e на страницу.
   - Риск: игра меняет путь к кэшу с версиями. Нужен понятный текст ошибки «ссылка не найдена».
2. **Экспорт истории в файл UIGF.** Сейчас история живёт только в `localStorage`: очистка
   данных браузера стирает её без возврата. Кнопка «Сохранить в файл» для обеих игр.
   - Файл читается обратно нашим же импортом (тест «экспорт, затем импорт даёт то же»).
3. **Импорт файла UIGF для Genshin.** Для Star Rail он есть, для Genshin нет.
4. **Статистика удачи по истории** (часть README, пункт 3, для обеих игр): среднее число круток
   на 5★, доля выигранных 50/50, самая длинная серия. Данные уже лежат в браузере.

Не входит: серверы Китая, перенос истории между устройствами через сервер.

### Этап 19. Хост для бота и Mini App (README, пункт 2)

1. Выбрать хост для Telegram-бота. SnapDeploy ботов запрещает и усыпляет контейнер.

2. Запуск: `python -m app.telegram` с `TELEGRAM_BOT_TOKEN`. Токен задаёт владелец на хосте.
   Токен, который однажды попал в чат, должен быть отозван в @BotFather.
3. Mini App: сайт внутри Telegram. Нужен постоянный HTTPS-адрес сайта.
4. Ответы бота со ссылкой на страницу персонажа на сайте.
5. До запуска бота для чужих людей: раздел о Telegram в политике конфиденциальности (этап 21).

## 5. Советы сверх плана

Не строить без согласия владельца.

1. **Экспорт истории в файл** — самый полезный совет: сейчас история теряется при очистке
   браузера. Поставлен в этап 17.
2. **Хостинг.** Пять деплоев в день и засыпание контейнера мешают проверке. Скриншоты из
   сессии заменяют большинство деплоев. Для запуска нужен хост без засыпания.
3. **Память о UID.** Сайт мог бы помнить последний UID на устройстве и открывать сборки сразу.
   Это новая запись в `localStorage`: описать в политике.
4. **Сравнение двух сборок** одного персонажа (до и после смены реликвии) на широком экране.
5. **Установка как приложение (PWA)**: значок на экране телефона, работа прогнозов без сети.
6. **Страница «Что нового»** для игроков после каждого обновления.
7. **Шрифт.** Проверка impeccable отметила Geist как слишком частый выбор. Менять только если
   владельцу он не нравится.

## 7. Правила, которые нельзя нарушать

- Секреты только в переменных окружения: не в репозитории, не в логах, не в чате.
- Ссылка на историю — секрет: не логировать, не хранить, не класть в URL запроса.
- Тесты не обращаются к Enka.Network и HoYoverse.
- Числа игры только из данных игры, не по памяти. Оценки сообщества подписывать.
- Никаких ссылок на другие трекеры на сайте.
- `./check.sh` проходит перед каждым пушем; пороги покрытия и правила линтера не ослаблять.
- Сначала компьютер, но 360px, поля 16px и цели касания 44px должны работать.
- Интерфейс на английском и русском.
- Всё, что просил владелец, либо построено, либо записано в план README со своим местом.
